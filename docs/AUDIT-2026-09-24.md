# Adversarial audit — 24 September 2026

> Historical audit, with follow-up notes recorded during development. Status
> reviewed 7 October 2026: local `.deb` installation and the five-target Docker
> matrix are now complete. Debian/Ubuntu/Mint/Kali mirror discovery and independent
> archive/suite selection have also been added; see [the mirror guide](MIRRORS.md).
> Those are no longer missing features or tests.
> See [current validation](QUALITY.md), [feature coverage](FEATURE-COVERAGE.md)
> and [distro results](DISTRO-TESTING.md). Counts, timings and scores below describe
> the earlier audit; they are retained as historical evidence, not a new score.

**Assessment at the time: 9.0/10 for release readiness. Not 10/10.**
The earlier 9.2 development-scope rating was too generous for a review that also
includes missing workflows, failure handling, accessibility and distribution.
These are engineering judgments, not measured probabilities of correctness.

`ORBIT_TEST_IM_MODULE` to opt into a dedicated input-method test. This isolates
the test environment, not a proven fix for the desktop IBus/GTK stack.

## Validation

- 58 backend/metadata/packaging/network tests and 35 GUI tests passed
  (93 distinct tests). The loopback HTTP test runs separately with
  ORBIT_NETWORK_TESTS=1. The 34-test GUI suite passed in 115.201 seconds;
  the new full-upgrade routing test passed separately.
- Real isolated APT/dpkg: refresh, install, upgrade, remove, install again, purge;
  same-version reinstall restores damaged files, autoremove retains conffiles;
  cancellation leaves files unchanged. Real helper review cancellation,
  approval, captured logs and removal also tested.
- Real helper pipe-loss test: losing the GUI before approval cancels without
  installing; losing it after approval still completes the isolated dpkg install.
  This is a connection-loss test, not a power-loss or forced-helper-kill test.
- GUI tests cover stale searches, missing/corrupt images, failed child processes,
  cancellation, close guards, kept-back states, recycled installed rows, 500-package
  history groups, short windows, protocol errors and progress/log floods.
- Ruff and wheel/source builds checked. No host packages or APT sources changed.
- Local .deb ownership/modes and policy scope verified. Shipped launcher isolation
  and dpkg install/replacement/removal tested in namespaces. This does not yet
  establish desktop Polkit-agent behavior on a real installed release.
- Read-only timings on this host: first installed snapshot plus metadata 2.054 s
  for 3,699 packages; cached snapshot 0.027 s; normal-upgrade policy snapshot
  1.275 s for 10 candidates; search for bash 1.511 s (200-result limit).
  These are individual local timings, not a performance guarantee.
- Recycled Installed list profile at 900×640, 10,000 fixture packages: model
  replacement 0.064 s, 205–206 live row containers across ten scroll positions,
  23.1 MiB additional peak RSS in that process. This includes model/widgets and
  allocator retention, not a claim of total application memory consumption.
- Weak-network coverage includes DNS failures, cancelled probes, body size limits,
  stalled/trickling HTTP, truncated responses, subsequent successful requests,
  failed APT refresh and download, cached browsing, and retry controls. Inactivity
  timeouts and body deadline checks do not establish a hard wall-clock limit for
  platform DNS resolution or every possible HTTP-header failure mode.

## Further fixes from the follow-up review

- Added Updates → Upgrade options → Review full upgrade. APT resolves dependency
  transitions; the existing plan lists removals before approval and still rejects
  held/protected/essential changes and unrequested downgrades. A real disposable
  repository verifies normal upgrade keeps a transition back, full upgrade lists
  the dependency removal, cancellation preserves state, and approval completes it.
- Home now inspects dpkg states and reports unfinished configuration separately
  from reinstallation requirements and broken dependencies. The existing repair
  review is offered for pending configuration. Unit tests cover state categories;
  a real unpack/configure fixture verifies detection and clearing. This does not
  establish automatic recovery from power loss or test every repair-helper failure.
- Added GUI assertions for recovery warning lifecycle and full-upgrade routing.

## Release gaps recorded at the audit (see current status above)

1. **Release acceptance:** the local Debian build now has a root-owned installed
   helper, scoped Polkit action and isolated layout/lifecycle tests. Real desktop
   authentication, multiple distro releases, public release metadata and licensing
   still need acceptance work. The development launcher continues to import a
   trusted checkout through generic Polkit authorization.
2. **Missing workflows:** no GUI for holds/unholds,
   local .deb installation or package-version selection at that time. Local archives
   have since been implemented and tested; holds/version selection still
   need explicit dependency plans and safety tests, not buttons around shell commands.
3. **Configuration decisions:** package configuration is retained automatically;
   there is no conffile diff/choice UI or general debconf integration. Arbitrary
   maintainer scripts and desktop authentication prompts have not been exercised.
4. **Accessibility and platforms:** no screen-reader acceptance test, keyboard-
   only end-to-end study, HiDPI matrix, or multiple distro/GTK/Wayland test matrix.
5. **Scale:** Installed now recycles widgets and has a 10,000-package profile.
   Search still has a bounded result ceiling; large real catalogues, artwork-heavy
   long sessions and slower machines need broader latency/memory measurements.
6. **Crash recovery:** normal failure, cancellation and lost GUI pipes are tested.
   Power loss, forced termination of the helper/dpkg and recovery after restart
   remain unproven. Connection survival is not transaction rollback or recovery.

The broader request to exceed other package managers is tracked in
[FEATURE-COVERAGE.md](FEATURE-COVERAGE.md), including multi-source discovery,
offline updates and batch selections. These are not represented as finished features.

## Package-row installation progress

APT installation callbacks can omit the architecture from the package identifier,
while reviewed rows and download callbacks use qualified names. Resolve unique
names against the approved plan and use an explicit architecture in APT's status
text when available; ambiguous identifiers are not assigned to an arbitrary row.
The isolated real APT test verifies unpacking addresses the same row as downloads.

Shared transaction dialogs now retain their searchable, recycled package rows
through execution. Each row shows its latest download, unpacking or configuration
message and progress bar. Updates continues to use its existing inline rows.
Installation bars pulse because APT's install percentage is transaction-wide;
only download byte counts provide per-package percentages. Progress state survives
filtering and row recycling; final success or failure remains explicit.

Follow-up validation: backend progress tests, real isolated APT stage identity,
shared-dialog pipe handshake, inline upgrade bars, filtered row state, large-plan
recycling and short-window layout all pass. Wheel, source and Debian builds pass.
